# scripts/verify-design-quality-ceilings.txt — RATCHET for Layer 4
#
# Measured 2026-08-11 at commit d08f0adc over the stylesheets App.razor
# actually links, plus apps/V1.App/wwwroot.  Regenerate the measurement with:
#   WSL_DUMP=1 ./scripts/verify-design-quality.sh
#
# These are CEILINGS, not targets.  The gate fails only when a number GROWS,
# so nothing has to be cleaned up for CI to pass — but nothing can quietly
# get worse either.  When a number drops the run says so and asks for the
# ceiling to be tightened; it does not fail, because failing an improvement
# would punish the exact work this layer exists to encourage.
#
# ── How far past the reference limits these sit ─────────────────────────
# The reference caps carried over from the origin repo are colours 60,
# spacings 20, font-sizes 10, icon-sizes 6 — and every one of ours is over,
# the typographic scale by more than 4x:
#
#   colours     129  vs  60   (the origin's worst app shipped 42)
#   spacings     34  vs  20
#   font-sizes   42  vs  10
#   icon-sizes   16  vs   6
#
# Worth reading against META-MODEL §9: the theme catalog defines FOUR font
# sizes and FIVE spacings as the closed vocabulary a tenant can drive.  The
# stylesheets ship 42 and 34.  The gap is not a token problem — the tokens
# are correct — it is that most declarations never reference them.  That is
# the single largest piece of visual debt these five layers measure, and it
# is recorded here rather than fixed, because collapsing 42 font sizes into
# 4 is a design decision with visible consequences on every screen.
#
# ── 2026-08-15: font-sizes 42 -> 39, and why the other three did not move ─
# 182 declarations whose literal equalled an existing token EXACTLY were
# rewritten to var(--ac-…) — proven zero-change against the computed style
# of 1,298 elements on 8 pages.  Only the typographic count moved, because
# only there did the app's de-facto scale intersect the token scale:
#
#   font-size   14px / 1rem / .875rem / 1.25rem / 1.5rem  ← ON the scale
#   radius      8 / 10 / 14 / 999 px                      ← ON the scale
#   spacing     4 / 8 / 12 / 16 / 20 px                   ← the token scale
#                                                            is 3.5/7/14/21/28
#                                                            (rem × 14px root):
#                                                            ONE value in common
#   colour      the invariant tokens matched 2 literal sites in the sheets
#
# So `spacings|34` is NOT laziness: substituting 12px or 16px for a token
# worth 14px is a visible change, and substituting only the accidental 14px
# would make a third of one row scale under density while its neighbours
# stay pinned — worse than uniform literals.  The measured decision table is
# docs/THEME-DEBT-DECISIONS.md.
